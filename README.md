# Хранилище учёток для теста

Статический каталог, который открывается сразу без входа.

Комплект для GitHub Pages содержит вымышленные учётки.

## Открыть сайт

Для локального запуска нужен Node.js 22 или новее. Дважды щёлкните **«Открыть сайт.cmd»** в корне проекта или выполните:

```sh
npm start
```

Откройте [каталог на localhost](http://127.0.0.1:4173/preview/project/). Для локального просмотра интернет не нужен. Ctrl+C останавливает просмотр.

## Изменить данные

Единственный актуальный источник — **`src/data/test_clients_simple.json`**. Скопируйте объект клиента в массив `clients`, отредактируйте значения и сохраните. Код менять не нужно.

```sh
npm run check:data
npm test
npm run build
```

Локальный просмотр читает исходный JSON. После правки достаточно обновить страницу. При публикации сборка копирует файл в `dist/data/test_clients_simple.json`. Папка `dist` исключена из Git.

Пример вымышленной записи:

```json
{
  "clients": [{
    "name": "Демо Клиент Вымышленный",
    "login": "TEST-LOGIN-001",
    "password": "NOT-A-REAL-PASSWORD",
    "id": "TEST-ID-001",
    "products": ["Кредитная карта (просрочка)", "Арест ФНС"],
    "available": true,
    "other_passwords": ["NOT-A-REAL-ALTERNATIVE"]
  }]
}
```

Основные поля: name, login, password, id, products, available. Дополнительно: access_note, other_passwords, no_products. Формальная схема — `src/data/test_clients_simple.schema.json`; runtime-валидатор `src/core.js` проверяет данные при сборке и загрузке. Ошибки содержат путь поля, но не значения.

Лимиты: до 1000 клиентов; name до 160 символов; login/id до 128; password и альтернативы до 256; до 50 продуктов по 500 символов; access_note до 1000; до 30 альтернативных паролей. Name, products и boolean available обязательны. Login/password/id допускают пустую строку, null или отсутствие: пропущенные логин/пароль делают учётку недоступной, отсутствие ID не блокирует. Неизвестные поля и управляющие символы запрещены.

## Поведение каталога

- Основные поля карточки: ФИО, единый логин, открытый пароль, ID; альтернативные пароли копируются отдельно. Телефона отдельной строкой нет.
- Продукты отображаются единственным блоком через « · », с мягкими цветами арестов, просрочек и блокировки карт. Повторяющих общих плашек нет.
- Пустой products с no_products: true → «Продуктов нет»; иначе → «Нет данных о продуктах».
- Доступность определяется available и наличием логина/основного пароля; причина берётся из access_note с добавлением пропущенных реквизитов без повторения уже указанной причины.
- Доступные учётки идут первыми, недоступные — внизу. Арест сам по себе не блокирует учётку.
- Поиск по ФИО, login, ID, продуктам и причине недоступности. Пароли в поиске не участвуют.
- Мультифильтры: OR внутри группы, AND между группами; «Все» очищает поиск и фильтры. Продукты определяются по строкам, новые формулировки попадают в «Другие продукты».
- Сетка по умолчанию 3 карточки, переключение на 4; на узких экранах адаптивно 2 или 1 колонка.
- Поле копируется нажатием с подтверждением. При запрете буфера браузером открывается ручной вариант.
- **Copy full** копирует ФИО, логин, основной пароль и ID отдельными строками. Пустое поле оставляет пустую строку.
- «Тест завершен» выпускает случайные пользовательские PNG; данные не меняются.

## GitHub Pages

1. Распакуйте архив и добавьте содержимое папки проекта в корень репозитория, включая `.github/workflows/pages.yml`.
2. В репозитории откройте **Settings → Pages → Build and deployment → Source** и выберите **GitHub Actions**.
3. Во вкладке **Actions** запустите **GitHub Pages → Run workflow** на основной ветке. Последующие изменения основной ветки запустят публикацию автоматически.
4. Адрес появится в задаче `deploy` и в **Settings → Pages**.

[Инструкция GitHub по выбору источника публикации](https://docs.github.com/en/pages/getting-started-with-github-pages/configuring-a-publishing-source-for-your-github-pages-site).

**Для публичного каталога используйте вымышленные записи.** Посетитель сайта может скачать весь JSON. Видимость сайта настраивается отдельно от видимости репозитория. [Настройки видимости GitHub Pages](https://docs.github.com/en/enterprise-cloud@latest/pages/getting-started-with-github-pages/changing-the-visibility-of-your-github-pages-site).

## Проверки

Команда `npm test` проверяет структуру JSON, поиск, фильтры, доступность, сборку и праздничную анимацию. Подробнее в [плане проверок](docs/QA.md).
