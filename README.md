# Хранилище учёток для теста · версия 2.1

Статический каталог без авторизации и backend. При открытии сразу показываются тестовые клиенты. Новый простой формат JSON, 50 клиентов, альтернативные пароли, поиск, фильтры, цвета меток, сетка 3/4 и коты сохранены.

## Открыть сайт

Дважды щёлкните **«Открыть сайт.cmd»** в папке над проектом или откройте `dist/index.html` в браузере. Вход и пароль каталога не нужны. Вся папка `dist` работает локально без сервера и интернета.

Для необязательного локального HTTP-просмотра нужен Node.js 22+:

```sh
npm start
```

Откройте http://127.0.0.1:4173/preview/project/. Сайт работает и в корне, и в подпути проекта. Ctrl+C останавливает просмотр.

## Изменить данные

Единственный актуальный источник — **`src/data/test_clients_simple.json`**. Скопируйте объект клиента в массив `clients`, отредактируйте значения и сохраните. Код менять не нужно.

```sh
npm run check:data
npm test
npm run build
```

После сборки откройте заново `dist/index.html` или обновите страницу. При HTTP читается `dist/data/test_clients_simple.json`; для локального `file://` автоматически создаётся `dist/data/clients-data.js` с теми же данными. Не редактируйте эти сгенерированные копии вручную.

50 исходных записей сохранены побайтно в рабочем JSON. `private/` — только оставшиеся локальные резервные копии прежней версии; приложение её не читает, они не участвуют в сборке. Авторизации, настройки пользователей и серверного API в текущей версии нет.

Пример вымышленной записи:

```json
{
  "clients": [{
    "name": "Демо Клиент Вымышленный",
    "login": "TEST-LOGIN-001",
    "password": "NOT-A-REAL-PASSWORD",
    "id": "TEST-ID-001",
    "products": ["Кредитная карта (просрочка)", "Арест ФНС"],
    "available": true,
    "other_passwords": ["NOT-A-REAL-ALTERNATIVE"]
  }]
}
```

Основные поля: name, login, password, id, products, available. Дополнительно: access_note, other_passwords, no_products. Формальная схема — `src/data/test_clients_simple.schema.json`; runtime-валидатор `src/core.js` проверяет данные при сборке и загрузке. Ошибки содержат путь поля, но не значения.

Лимиты: до 1000 клиентов; name до 160 символов; login/id до 128; password и альтернативы до 256; до 50 продуктов по 500 символов; access_note до 1000; до 30 альтернативных паролей. Name, products и boolean available обязательны. Login/password/id допускают пустую строку, null или отсутствие: пропущенные логин/пароль делают учётку недоступной, отсутствие ID не блокирует. Неизвестные поля и управляющие символы запрещены.

## Поведение каталога

- Основные поля карточки: ФИО, единый логин, открытый пароль, ID; альтернативные пароли копируются отдельно. Телефона отдельной строкой нет.
- Продукты отображаются единственным блоком через « · », с мягкими цветами арестов, просрочек и блокировки карт. Повторяющих общих плашек нет.
- Пустой products с no_products: true → «Продуктов нет»; иначе → «Нет данных о продуктах».
- Доступность определяется available и наличием логина/основного пароля; причина берётся из access_note с добавлением пропущенных реквизитов без повторения уже указанной причины.
- Доступные учётки идут первыми, недоступные — внизу. Арест сам по себе не блокирует учётку.
- Поиск по ФИО, login, ID, продуктам и причине недоступности. Пароли в поиске не участвуют.
- Мультифильтры: OR внутри группы, AND между группами; «Все» очищает поиск и фильтры. Продукты определяются по строкам, новые формулировки попадают в «Другие продукты».
- Сетка по умолчанию 3 карточки, переключение на 4; на узких экранах адаптивно 2 или 1 колонка.
- Поле копируется нажатием с подтверждением. При запрете буфера браузером открывается ручной вариант.
- «Тест завершен» выпускает случайные пользовательские PNG; данные не меняются.

## Размещение

Копируется вся папка `dist`, без изменений относительных путей. `.gitlab-ci.yml` снова содержит GitLab Pages: проверки, сборка и публикация основной ветки; рассчитан на GitLab 17.10+ и Node 24. Для банковского контура можно заменить образ CI разрешённым внутренним. Внешняя публикация не выполнялась.

По запросу пользователя пункт о серверной авторизации отменён. **JSON и JS-слепок входят в статическую сборку и доступны всем, кто может открыть сайт.** Статический сайт не обеспечивает секретность; при необходимости доступ ограничивается корпоративной сетью/хостингом. Пароли не записываются приложением в localStorage, URL или аналитику; внешних API, CDN и шрифтов нет.

Архив 2.1 содержит рабочие данные и готовую статическую сборку. Он заменяет серверный архив 2.0 для текущего сценария запуска.

## Проверки

11 автоматических проверок: схема JSON, описание/пустые продукты, доступность, поиск без паролей, фильтры, исходные записи без изменения, офлайн-слепок и безопасное экранирование, отсутствие формы/endpoint-ов авторизации, праздничные PNG и очистка анимаций. Подробнее — `docs/QA.md`.
